# API 同步配置指南

Tempus 支持从公司打卡系统 API 同步工时数据，将打卡记录自动转换为每日工时条目。

## 功能概述

- 从远程 REST API 获取打卡记录
- 自动将多条打卡记录转换为单条工时记录（取第一次上班打卡和最后一次下班打卡）
- 支持多种认证方式（Bearer Token、Cookie、自定义请求头）
- 支持 GET/POST 请求方式
- 灵活的字段映射配置

## 配置入口

在应用侧边栏点击「设置」图标，即可进入 API 同步配置页面。

## 配置项说明

### 基础配置

| 配置项 | 说明 | 示例 |
|--------|------|------|
| API 地址 | 打卡记录接口的完整 URL | `https://api.company.com/punch/list` |
| 认证方式 | 接口认证类型 | `Bearer Token` / `Cookie` / `自定义请求头` / `无认证` |
| 请求方式 | HTTP 方法 | `GET` 或 `POST` |

### 认证配置

#### Bearer Token 认证

适用于使用 JWT 或 OAuth Token 的 API：

```
Authorization: Bearer <your_token>
```

在「Token」输入框填入 Token 值即可。

#### Cookie 认证

适用于基于 Session 的认证系统：

```
Cookie: session_id=abc123; user=admin
```

在「Cookie」输入框填入完整的 Cookie 字符串。

#### 自定义请求头

适用于特殊认证方式（如 API Key），需要在代码中配置 `customHeaders` 对象。

### 高级配置

#### 请求体模板（POST 请求）

用于构建 POST 请求的 JSON 请求体，支持以下占位符：

| 占位符 | 说明 | 示例值 |
|--------|------|--------|
| `{YEAR}` | 年份 | `2026` |
| `{MONTH}` | 月份 | `1` |
| `{DAYSTART}` | 月初日期 | `2026-01-01` |
| `{DAYEND}` | 月末日期 | `2026-01-31` |
| `{TIMESTART}` | 月初时间 | `2026-01-01 00:00:00` |
| `{TIMEEND}` | 月末时间 | `2026-01-31 23:59:59` |
| `{TOKEN}` | 配置的 Token | - |

**示例请求体模板**：

```json
{
  "startDate": "{DAYSTART}",
  "endDate": "{DAYEND}"
}
```

#### 响应数据路径

指定打卡记录数组在响应 JSON 中的路径。

**示例响应**：

```json
{
  "code": 0,
  "data": {
    "records": [
      { "punchTime": 1704067200, "punchType": "上班", "remark": "" }
    ]
  }
}
```

对应的响应路径为：`data.records`

#### 字段映射

配置 API 响应中各字段的名称，默认值如下：

| 字段 | 默认映射 | 说明 |
|------|----------|------|
| 打卡时间 | `punchTime` | 时间戳字段 |
| 打卡类型 | `punchType` | 类型字段（上班/下班）|
| 备注 | `remark` | 备注字段 |

如果 API 返回的字段名不同，请相应修改。例如 API 返回的是 `check_time`，则将打卡时间字段设为 `check_time`。

#### 时间戳格式

| 格式 | 说明 |
|------|------|
| 秒级时间戳 | Unix 时间戳（秒），如 `1704067200` |
| 毫秒时间戳 | Unix 时间戳（毫秒），如 `1704067200000` |
| 日期时间字符串 | ISO 格式，如 `2026-01-01 09:00:00` |

#### 默认休息时间

每日工时的默认午休时间（分钟），用于计算有效工时。默认值为 `60` 分钟。

## 数据转换逻辑

同步时，系统会按以下规则将打卡记录转换为工时条目：

1. **按日期分组**：将所有打卡记录按日期分组
2. **确定上班时间**：取当天第一条「上班」类型的打卡记录时间
3. **确定下班时间**：取当天最后一条「下班」类型的打卡记录时间
4. **容错处理**：如果没有明确的上班/下班类型，则使用当天第一条和最后一条打卡记录

**打卡类型识别规则**：
- 上班：包含「上班」或「checkin」（不区分大小写）
- 下班：包含「下班」或「checkout」（不区分大小写）

## 使用示例

### 典型公司打卡 API 配置

假设公司打卡 API 接口如下：

- **接口地址**：`https://hr.company.com/api/attendance/records`
- **请求方式**：POST
- **认证方式**：Bearer Token
- **请求体**：`{"month": "2026-01"}`
- **响应格式**：

```json
{
  "success": true,
  "result": [
    {
      "timestamp": 1704067200,
      "type": "上班",
      "note": "正常打卡"
    }
  ]
}
```

**配置方式**：

1. API 地址：`https://hr.company.com/api/attendance/records`
2. 认证方式：Bearer Token
3. Token：填入你的访问令牌
4. 请求方式：POST
5. 请求体模板：`{"month": "{YEAR}-{MONTH}"}`
6. 响应数据路径：`result`
7. 字段映射：
   - 打卡时间：`timestamp`
   - 打卡类型：`type`
   - 备注：`note`
8. 时间戳格式：秒级时间戳

## 常见问题

### Q: 同步失败显示「HTTP 错误: 401」

A: 认证信息无效，请检查 Token 或 Cookie 是否正确、是否过期。

### Q: 同步失败显示「响应路径不是数组」

A: 响应数据路径配置错误，请检查 API 实际返回的 JSON 结构。

### Q: 同步后工时记录显示不正确

A: 请检查：
1. 时间戳格式是否正确（秒/毫秒）
2. 字段映射是否与 API 返回的字段名一致
3. 打卡类型字段是否包含「上班」/「下班」关键词

### Q: 如何获取公司 API 的 Token？

A: 通常可以从公司内部系统的开发者控制台获取，或者通过浏览器开发者工具查看网络请求中的认证信息。具体方式请咨询公司 IT 部门。

## 安全提示

- Token 和 Cookie 等认证信息存储在本地 SQLite 数据库中
- 请勿将包含敏感信息的配置文件分享给他人
- 建议使用专门的 API 访问令牌，而非个人账户密码
